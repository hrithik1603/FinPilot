The Honest Verdict

TreasuryFlow is a genuinely impressive solo-built product. Very few developers — let alone student developers — build a full treasury management system with maker-checker workflows, live benchmark data, dynamic borrowing schedules, and NAV-based mutual fund valuation. The architecture is clean and the financial intuition is mostly sound.

The app scores 7.0 / 10 overall. The single biggest drag is the 2.5 / 10 documentation and the calculation accuracy gaps (Quick Ratio bug, hardcoded alerts, missing OI weights). These are not feature gaps — they are credibility killers in a client validation conversation. Fix those three things and the app is an honest 8.0 / 10.

Compared to paid alternatives like CashAnalytics (~$500/mo) or Kyriba (~$2,000/mo), TreasuryFlow already matches 70–80% of core feature coverage for the Indian SME market. That's remarkable for a v0 product built by one person.

Top 5 Actions to Reach 8.5 / 10
1

Fix Quick Ratio Bug

Replace the hardcoded divisor of 1 with 'N/A' when no 30-day schedules exist. 1-line fix, highest-visibility metric on the Liquidity page.

2

Remove Hardcoded Alerts

Make Critical Alerts and Invest Surplus dynamic, or remove them entirely. Hardcoded demo data is the first thing any client catches in a live demo.

3

Rewrite the README

Add project overview, tech stack, Supabase setup, .env vars, and a screenshot. Currently it is the default Vite template — a critical red flag for validation.

4

Add otherInvestments Weight

Add oiWeight to portfolio allocation so all asset class weights correctly sum to 100%. Simple fix in dashboardData.js.

5

Fix 30/360 Day Clamping

In borrowingCalculations.js, clamp both d1 and d2 independently per ISDA 30/360 convention. Affects all fixed-rate borrowing interest calculations.
